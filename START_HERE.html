Fix one button, three ways

An icon-only button looks fine but a screen reader user hears only "button". This artifact walks one visitor through that bug in under two minutes. First a tool finds it and proposes the fix. Then a 3D explainer shows why the fix works. Last, a short game lets the visitor fix the same kind of problem themselves. Everything runs in a browser from this folder, with no install and no internet needed.

1

Find it

Check a React component, accept the fix for the icon button and watch the re-check pass. (About 30 seconds.)

 2

See why

Follow the same button from JSX to DOM to accessibility tree to screen reader, before and after the fix. (About 45 seconds.)

 3

Practice

"Sounds Wrong": find the three broken parts of a card that looks finished, turn it over to see its accessibility tree, and clear three cards. No timer, and new problems every round. (About 45 seconds for one card.)

Why these tools

I built everything as static web pages because the people I want to hire me are front-end teams, and they ship accessible interfaces in the browser. Three.js draws the explainer and the game, but every word and control also exists in the page itself, so the pieces work with a keyboard and a screen reader, which is the skill the work is meant to show.

How it works inside: each page runs on small named state machines. See STATE_MACHINES.md in this folder.
